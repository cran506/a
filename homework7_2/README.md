# 第七章课后作业 7-2：液压 MPC 预测时域实验

`work_7_2.py` 在同一阀控液压缸对象上扫描预测时域 $N\in\{5,10,15,20,30,40,50\}$。采样周期为 1 ms，位置参考在 0.01 s 从 0 跳至 50 mm，仿真到 0.15 s。每个控制周期用**当前真实对象状态**重新建立局部预测、求解 CVXPY 二次规划，只执行所求序列的第一个电压。四联图展示 $N=5,20,50$ 的位移、电压、有杆腔压力，及全部七组的压力与计算时间。

## 运行

在本目录执行：

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python work_7_2.py
```

Windows 可将 `.venv/bin/python` 换成 `.venv\Scripts\python.exe`。单组调试可用 `python work_7_2.py --horizon 20 --no-plot --progress`；`--config` 和 `--output-dir` 可指定配置与结果目录。默认完整扫描会在 `outputs/` 生成 `horizon_comparison.png` 和定量表。若需要重新核验文件，执行 `python verify_experiment.py --output-dir outputs --strict`。闭环中含非线性 ODE 积分与多次局部优化，完整扫描的墙钟时间依机器而变。

本目录附 `materials/chap07-ppt.pdf` 与抽取文本以便核对章节；运行只依赖 Python 源码和 JSON 配置。课程用物理参数见 `physical_config.json`、`classroom_config.json`、`experiment_config.json`，是公开的**课堂仿真假设**，不应表述为实机辨识结果。

## 模型与约束

真实对象 `hydraulic_plant.py` / `twin_adapter.py` 保留阀动态、硬死区、混合静摩擦、容腔压缩性、泄漏和补油；`GreyBoxModel` 用可微的近似做预测与雅可比线性化。真实运动和压力曲线取自前者，预测约束检查取自后者。因此“模型预测满足上限”与“真实对象整个采样间都不越限”是两项独立检查。

此实现的物理状态是 `[相对位移 mm, 速度 m/s, P1 MPa, P2 MPa, 阀位等效 V]`。再加上上一周期实际控制电压，增广状态为 **6 维**；教材五维增广形式是较简化的对象。当前控制器对未来电压增量 ΔU 优化，保留局部仿射项。`mpc_core.py` 负责滚动线性化、凝聚矩阵 $F,\Phi$、海森矩阵 $H$、约束与非线性回验；`cvxpy_mpc.py` 将同一个 QP 交由缓存的 CVXPY/OSQP 问题求解，并检查原始约束和 KKT 残差。

实际电压限制为 ±10 V，每个 1 ms 的变化限制为 ±4.5 V。控制器的有杆腔 $P_2$ 预测节点上限设为 **20.5 MPa**，相对作业的真实安全线 **21.0 MPa** 留有 0.5 MPa 裕量；默认只给 $P_2$ 设置上限，不能据此断言 $P_1$ 也受到硬保护。位置、速度与电压增量的权重和末端代价调度均在 `experiment_config.json` 中公开。

若局部 QP 失败，或解未通过非线性压力回验，`safety_restoration.py` 会从历史移位方案与有限个目标电压生成候选序列，逐一复查增量、电压和非线性预测压力约束，仅施加通过复查的首个命令。此种失败后的恢复记为 `status_code=3`。若控制器已接受重新验证的历史移位方案，还会尝试独立的有限网格改进：只有候选同样通过非线性约束复查，且原目标值改善超过 1% 和绝对阈值，才替换原方案；替换记为 `status_code=4`，否则保留已验证的移位方案（`status_code=2`）。改进是 QP 之后的候选搜索，**不是 QP 最优解**，也不证明递归可行。若失败恢复时无候选通过，仿真明确终止并记录失败时间，图中不会补画虚构的安全轨迹。真实 $P_2$ 的安全结论最终还须检查积分器保存的采样间压力极值。

## 结果文件与指标口径

`outputs/N05.csv` 等文件逐采样记录位移、速度、压力、阀位、电压、耗时和控制状态；`N05_pressure_trace.csv` 等保留高密积分时间轴和两个腔的压力，压力峰值取此文件。`N05_solver_logs.json` 等包含每次局部 QP 的诊断、预测轨迹、失败恢复和移位方案改进记录。`summary.json` 给出七组的超调、压力峰值、恢复与改进次数、时间统计和矩阵维度；`validation.json` 由核验脚本写入。四联图的数据来自这些闭环结果，不在绘图代码中注入示意超调或压力波形。逐图原因见 [reference_comparison.md](reference_comparison.md)。

状态码用于区分实际施加的命令：`1` 为 MPC 已接受方案，`2` 为经复查的历史移位方案，`3` 为 QP 失败后的安全恢复，`4` 为移位方案经网格搜索改进，`0` 为指令前或末端观测，`-1` 为无可施加命令而终止。`3`、`4` 都必须计入实际控制决策的耗时，但不能计作新的成功 QP。

耗时有三种口径，不能混用：

| 指标 | 含义 |
| --- | --- |
| `solver_attempt` | 从逐步求解日志提取每次 QP 的 OSQP 底层耗时；四联图（d）同时绘制中位数和均值，汇总表另存 P95。 |
| `solver` / `solver_time_ms` | 一个控制周期内各次局部 QP 的 OSQP 底层耗时合计；汇总表给出其统计。 |
| `cvxpy_call` / `cvxpy_wall_ms` | `Problem.solve()` 的墙钟时间，包括 CVXPY 与求解器接口的开销。 |
| `whole_controller` / `controller_wall_ms` | 整个控制步骤的墙钟时间，包括建模、滚动线性化、优化、非线性验证，以及必要时的安全恢复或移位方案改进。 |

`solver_attempt` 逐次统计日志中有底层耗时的 QP 尝试；`solver` 与 `cvxpy_call` 的汇总统计只取状态码 1/2 的控制周期。恢复和改进另设次数，均计入完整控制步骤。`whole_controller.over_1ms_fraction` 衡量名义 1 ms 截止时间的超时比例。普通桌面 Python 计时不是实时控制器认证，也不能把“OSQP 求解低于 1 ms”直接解释为“整个 CVXPY 控制周期低于 1 ms”。

## 与参考示意图的差异

教材习题规定了预测时域对超调、压力约束和耗时的**定性比较**，没有固定某台机器的 OSQP 毫秒数，也没有规定参考图每段压力的回路参数。本实验沿用公开的闭中位四通阀液压对象，其回油阀口与供油阀口采用同一节流系数。高速伸出时有杆腔约需 4–5 MPa 推动回油通过节流口，不能直接得到参考示意图的近零巡航压力。制动后阀回中位，两腔被封闭；`C_ep=0`，有限的内泄漏不会在几十毫秒内把有杆腔从约 14 MPa 卸回 2 MPa。要出现参考图那种快速卸压，必须明确增加回油口能力或卸荷/溢流通路，并在真实对象与预测模型中同时实现、重新验证全部时域。绘图没有对压力做平移、重置或削顶。

短时域控制器在终点附近可能交替打正、反电压，触发摩擦的多次粘滑切换。`experiment_config.json` 的控制权重直接影响该振荡，调参须对全部时域一视同仁，并重跑真实压力检查。图 (d) 现区分**每次 QP 的中位耗时与均值**，以避免把每控制周期的两三次局部 QP 合计误读为一次 QP；`summary.json` 仍保留单次尾部耗时、周期 QP 合计和完整控制周期耗时，便于判断真正的 1 ms 截止风险。

## 研讨要点

1. 对比 $N=5$ 与 $N=20$ 的峰值位移、限压边界附近控制电压、恢复事件及真实 $P_2$ 峰值，解释视野过短时跟踪精度与约束维护为何发生冲突。先看 `summary.json` 和逐周期日志，再依据实测曲线作结论。
2. 比较 $N=20$ 与 $N=50$ 的位置/压力收益，以及三种耗时指标与 1 ms 采样周期。短时域可能出现非单调表现，不能预设每组都严格改善。
3. 本实现的凝聚矩阵尺寸为 $\Phi\in\mathbb{R}^{6N\times N}$、$H\in\mathbb{R}^{N\times N}$，存储项数随 $N^2$ 增长；常规密集分解的计算量可达 $O(N^3)$。这不是“矩阵维度指数级膨胀”。选取 $N$ 应同时考虑制动视野、可行性、安全裕量和所用硬件上的完整控制周期。
