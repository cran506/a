## 安装与运行

需要 Python 3.11 或更新版本、`g++` 和中文字体（如 Noto Sans CJK SC）。C++ 只加速同一液压 ODE 的积分，SAC 由 Stable-Baselines3/PyTorch 实际训练。

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python drl_hydraulic_lab.py --mode all --reuse-model
```

随项目提供的检查点已完成 **1,000,000 步**孪生交互。上述命令保留该检查点，重新评估、蒸馏、量化、验证、绘图并生成交付包。若要重新训练：

```bash
python drl_hydraulic_lab.py --mode all --timesteps 1000000 --seed 2026
```

重新训练会产生新的策略和日志，耗时依机器而变，不能沿用此次性能数字。其他入口：

```bash
python drl_hydraulic_lab.py --mode evaluate
python drl_hydraulic_lab.py --mode normalize
python drl_hydraulic_lab.py --mode safety
python drl_hydraulic_lab.py --mode report
python test_physics_safety.py --write-summary
python verify_experiment.py
python -m unittest -v
```

`evaluate` 重做四策略评估、压缩和归一化诊断；`safety` 可独立运行约化模型。`all` 还会重算独立物理/安全证据，再验证并打包。当前云环境解释器为 `/workspace/.venvs/chapter8/bin/python`。没有用预设响应替代强化学习的分支。

## 本次实际结果

原 1M 检查点与训练日志保持不变，历史 CPU 训练约 1378 s。本次重新生成评估和压缩工件。恢复要求为峰值后直到记录结束始终满足 `|速度误差|≤1 mm/s`，并保留至少 50 ms 证据。

| 策略 | 最低速度误差 (mm/s) | 故障后 RMS (mm/s) | 末 0.1 s 均值 (mm/s) | 恢复时间 |
| --- | ---: | ---: | ---: | --- |
| PID | −53.824 | 10.517 | +4.997 | 本窗口未恢复 |
| 标称前馈 | −54.105 | 26.457 | −25.297 | 本窗口未恢复 |
| SAC FP32 | −32.455 | 4.110 | −0.028 | 0.068 s |
| 剪枝 INT8 v3 | −33.351 | 4.311 | −0.073 | 0.050 s |

显示窗口 FP32/INT8 速度 RMS 差为 **0.612 mm/s**；完整 0.3–1.0 s（含预运行）为 **1.360 mm/s**。INT8 在此判据下恢复较早，不代表量化普遍提高控制精度，其谷值与故障后 RMS 仍略差。

当前谷值比参考约 −14.1 mm/s 更深。故障瞬间 FP32 已输出约 **9.957 V**，接近 +10 V 上限；250 kg 滑块、5000 N 负载及额外建压所需流量形成实际瞬态限制。主动升压和快速恢复趋势成立，但不能通过平滑或重新标注把谷值改成参考值。

训练原始平均每步奖励从首条约 −14096.9 改善至末条 −6.385，末条电压微分熵约 0.251 nat。参考奖励 −2、熵 0.35、−14.1 mm/s、9.10 V 是教学示意，不作为结果赋值。

## 机理模型、观察和奖励

`physical_config.json` 公开独立教学标度：A1=3.8×10⁻⁴ m²、A2=2.1×10⁻⁴ m²、质量 250 kg、供油压力 21 MPa、标称模量 1 GPa、库伦摩擦 1200 N、阀死区 ±0.5 V。它不是此前 A1=0.01 m² 装置的辨识参数。

`hydraulic_twin.py` 与 `native_twin.cpp` 实现相同 `[x,v,P1,P2]` 非线性方程，含变容积、有向孔口、压缩性、内泄漏、补油和泄压。独立 Python RHS/Radau 复核 C++ 细分 RK 积分；状态没有事后裁剪。β 减半主要改变压缩瞬态，带载稳态电压增加来自负载使阀口压差收窄，不把 β 减半直接当作流量减半。

为包含容积位置、两腔压力、参考和历史输入，将课件五维示例扩展为十维：位置误差、速度误差、加速度误差、P1、P2、绝对位置、参考速度、参考加速度、上一实际电压、供油压力。运动误差采用 mm、mm/s，压力采用 MPa；准确顺序见 `hydraulic_env.py`。

每步在物理单位下计算奖励：

```text
r = -100 e_mm² - 0.1 u_V² - (u_V-u_prev_V)²
    + 2（当 |e_mm|<0.2）
```

失败终止额外扣 500 并单独记录。Monitor 保存原始奖励，优化器使用 0.01 倍数值缩放。`reward_mean` 是每个回合总回报除以真实长度，再平均最近 30 回合；不是回合总奖励。图中大负值使用明确标注的对称对数轴，后期奖励另用线性刻度局部放大。

每回合随机化质量 ±20%、初始模量 600–1400 MPa、摩擦 ±30%，另公开加入随机负载/刚度故障增强。因此 5000 N/50% 测试属于训练包络覆盖下的仿真鲁棒性检验，不是真机或完全未知工况的外推证明。

## 经验 Z-score 与训练历史

历史 1M 训练使用固定工程均值/尺度，不能改称样本拟合的 Z-score。新增 `observation_normalization.py` 从 **12,000 条**训练校准记录重建原始观察，拟合经验统计量，在 **4,000 条**留出记录上验证。

令旧输入为 `(raw−μ_old)/σ_old`、新输入为 `z=(raw−μ_new)/σ_new`，actor 首层等价变换为：

```text
W_new = W_old · diag(σ_new/σ_old)
b_new = b_old + W_old · ((μ_new−μ_old)/σ_old)
```

本次留出动作最大差约 **1.47×10⁻¹⁵**，工件为 `models/actor_empirical_zscore.npz`。常量通道尺度取 1，变换后为零，无法也无需满足单位方差。这是训练后的等价坐标变换，没有新增 SAC 交互步数或修改训练历史；默认评估兼容原检查点尺度。

## 熵与颤振的边界

熵由 actor 在真实 replay 状态上的 tanh 修正对数概率计算，电压单位换算为 `H(u)=H(a)+ln(10)`。连续分布微分熵可以为负；归一化动作上限为 ln(2)，电压空间上限为 ln(20)。目标电压熵 0.35 是显式参数，末条实际约 0.251，不称为未指定却必然涌现的常数。

四策略评估采用确定性均值动作，不叠加人工正弦 dither。当前摩擦是连续 tanh-Stribeck 滑动近似，未包含严格静摩擦粘住/释放，因此本图不能单独证明消爬行。随机动作的死区概率穿越与低速爬行需要另设带种子、频谱及集合值摩擦的专项测试。

## HOCBF 安全演示

`safety_config.json` 声明二阶教学模型 `x_dot=v, v_dot=2640u−14v`（mm、mm/s），机械区间 0–100 mm，内缩保护区 1.2–98.8 mm。κ1=κ2=49，对应 α_sum=98、α_product=2401。传播、QP、诊断和独立验证读取同一配置；这不是四状态训练对象的参数辨识。

+8.5 V 未保护指令在 **0.104891 s** 首次触及 100 mm。HOCBF 在 **0.065 s** 开始干预，最低电压 **−3.091605 V**，1 s 末渐近至 **98.8 mm**；0.25 s 位置为 98.7667 mm。首次触边后未保护 CSV 为 NaN，表示实验结束，不补造碰撞后轨迹。

标量 QP 做最小距离区间投影，检查初始 h/ψ1 和整个 1 ms ZOH 区间的不等式；不可行时抛错。128 个随机可行情形另用 DOP853 复核。`HOCBFSafetyFilter` 保留旧构造默认值用于接口兼容，实验由新配置明确选择上述参数。

四状态压力对象具有更高相对阶数，二阶证书不能直接转移到该模型或真实硬件，也不宣称未知扰动下绝对安全。

## 70% 剪枝、INT8 v3 与实际计时

按幅值排序剪除约 70% 非结构化连接，固定掩码后作 **8,000 步 PyTorch 蒸馏＋15,000 步 NumPy 余弦 Adam 精修**。23,000 步属于压缩优化，不计入 1M SAC 环境交互；精修只按校准 MSE 选取，不用留出或闭环测试选模型。

ReLU 正对角跨层等价缩放（CLE）保持浮点函数及零掩码。输入 SmoothQuant α 在最终 **12,701 条**校准记录上按 INT8 相对剪枝 FP32 动作 MAE 从 0.25/0.5/0.75 选择，本次为 **0.75**。其中包括 701 条声明的 FP32 commissioning 故障观察，该轨迹不是完全留出实验；另外 4,000 条 replay 留出观察不参与选参。

v3 使用逐输出通道对称 INT8 权重（零点 0）、仿射 INT8 隐层激活、INT32 点积/偏置、INT64 定点重缩放。末层保留 INT32 logits，到最终 tanh 边界才反量化。输入前缀、输入量化及 tanh 保留浮点，不称全路径全 INT8。加载器兼容 v1/v2/v3，独立加载不依赖原 FP32 权重。

| 工件/参考路径 | 实际文件字节 | CPU batch=1 中位数 (ms) | P95 (ms) |
| --- | ---: | ---: | ---: |
| FP32 | 19696 | 0.008212 | 0.008716 |
| 剪枝 FP32 | 9396 | 0.008252 | 0.008473 |
| INT8 v3 | 9171 | 0.036786 | 0.051791 |

实际零权重比例为 **69.9792%**，INT8 工件相对 FP32 缩小约 **53.4%**，包含逐通道元数据开销。当前 NumPy 整数路径比 FP32 更慢；计时仅含 actor 内核及前缀/tanh，不含传感通信、SB3 API、ODE 和 HOCBF，不能套用课件 92.5% 压缩率或 MCU 时间。非结构化零权重仍按稠密数组计算，不等于同比运算减少。

本项目完成孪生训练与参数失配仿真，没有真机少样本微调、ONNX 静态 C 固件或 MCU 上机测试。课后作业 8-4 的随机化宽度比较不属于本次课堂四策略实验。
