## 安装和运行

需要 Python 3.11 或更新版本、`g++` 和中文字体（如 Noto Sans CJK SC）。C++ 仅加速同一液压 ODE 的积分，不替代 SAC，也不生成模板数据。

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python drl_hydraulic_lab.py --help
python drl_hydraulic_lab.py --mode all --timesteps 1000000 --seed 2026
```

当前云环境的解释器为 `/workspace/.venvs/chapter8/bin/python`。入口按提供的依赖检查逻辑导入 `gymnasium` 与 `stable_baselines3.SAC`，缺库就打印安装提示并退出；没有“未安装强化学习库时用解析曲线代替训练”的分支。已有训练模型时可跳过重训；`reporting.py` 可在已有真实输出后单独重新生成图表：

```bash
python drl_hydraulic_lab.py --mode all --reuse-model
python drl_hydraulic_lab.py --mode evaluate
python reporting.py
python -m unittest -v test_edge_exporter
python safety_experiment.py
```

本次依赖验证使用 Python 3.12.14、PyTorch 2.14.1+cpu、Gymnasium 1.4.0、Stable-Baselines3 2.9.0；`pip check` 通过。项目入口和报告模块把 Matplotlib 缓存放在 `/tmp`，适用于主目录只读的云环境。

| 子图 | 运行数据与含义 |

四策略采用相同四状态液压方程、初态、参考速度和故障。在全局 0.3s 从同一个巡航平衡初态开始独立运行，0.5s 施加故障，持续至 1.0s。结果图显示 0.4–1.0s；0.3–0.4s 的共同预运行全部保留在原始 CSV 中，用于让实际控制器在故障前进入工作状态。没有平滑原始数据，也没有把不同运行的曲线拼起来。

传统组是固定参数的位置 PID，包含已建立巡航点的初始电压偏置、位置/速度误差反馈、不完全微分和条件积分抗饱和。具体增益及单位公开在 `baseline_pid.py`；它不根据故障在线改参，也不读取外部负载标签。标称前馈组使用空载平衡孔口/受力方程的真实逆解，没有压力增益调度或积分反馈。因此该组的负载后残差来自标称模型失配，不能写成“前馈 + PID”的静差。

## 本次真实运行结果

SAC 完成 **1,000,000 步**孪生交互，CPU 训练约 **1378s**。故障后统计如下，恢复要求在峰值后直至记录结束都满足 |误差|≤1mm/s，且至少保留 50ms 证据：

| 策略 | 最低速度误差 mm/s | 故障后误差 RMS mm/s | 末 0.1s 误差均值 mm/s | 恢复时间 |
|---|---:|---:|---:|---|
| PID | −53.824 | 10.517 | +4.997 | 本窗口未恢复 |
| 标称前馈 | −54.105 | 26.457 | −25.297 | 本窗口未恢复 |
| SAC FP32 | −32.455 | 4.110 | −0.028 | 0.068s |
| 剪枝 INT8 | −32.971 | 4.256 | −0.137 | 0.450s（量化纹波使严格恢复较晚） |

SAC 的主动升压和较快恢复趋势与课件一致，但实际谷值较参考的约 −14.1mm/s 更深，并有正向回弹，不能写成逐点复现。INT8 与 FP32 的核心瞬态接近，显示窗口的速度 RMS 差为 **0.753mm/s**，完整 0.3–1s（含预运行）为 **1.228mm/s**；量化纹波使严格恢复较晚，它们没有完全重合。默认输出不作控制电压或曲线的后处理平滑。

原始训练奖励从首条约 −14096.9 改善至最后一条 −6.385，最后一条电压微分熵约 0.251nat；这些不是课件固定的 −2 和 0.35。工件 FP32 / INT8 分别为 **19696 / 4940 字节**，本次 NumPy CPU 推理中位数约 **0.00837 / 0.04970ms**。整数原型没有在这台 CPU 上更快，详细 P95 和留出误差见 Word 短表及 `metrics.json`。

## 液压对象及参数标度

`physical_config.json` 公开本次紧凑缸配置：A1=3.8×10⁻⁴m²、A2=2.1×10⁻⁴m²、质量 250kg、供油压力 21MPa、标称油液体积模量 1GPa、库伦摩擦 1200N、阀死区 ±0.5V。这是独立教学标度，**不是此前 A1=0.01m² 液压缸的原辨识参数**。缩小有效面积后，5000N 会明显改变阀口压差，才能研究本章设定的重载控制问题。

`hydraulic_twin.py` 和 `native_twin.cpp` 实现相同的四状态 `[x,v,P1,P2]` 非线性方程，包括变腔容积、有向孔口压差流量、两腔压缩性、内泄漏、低压补油及物理泄压。C++ RK 积分采用内部细分；状态不经人为裁剪。Python RHS 独立保留用于数值复核。

摩擦使用连续 tanh-Stribeck 滑动近似，没有集合值静摩擦的严格粘住/释放分支。因此本项目不能宣称通过真实静摩擦实验验证了 SAC 的颤振消爬行效应。油液体积模量主要改变压缩瞬态；故障后的稳态阀电压变化来自实际负载导致的压差流量增益变化，不把“β 减半”直接当成稳态流量减半。

## 状态、奖励和域随机化

原五维 `[e,de,dde,PL,Ps]` 不包含绝对位置、两腔独立压力或历史输入。本实现扩展为十维参考观察量：位置误差、速度误差、加速度误差、P1、P2、绝对位置、参考速度、参考加速度、上一实际电压、供油压力。运动量转换到 mm、mm/s，压力转换到 MPa 后按公开工程尺度标准化。它是固定尺度缩放，不宣称样本严格满足零均值单位方差。准确顺序、符号及尺度以 `hydraulic_env.py` 为准。

动作是 `a∈[-1,1]`，物理电压 `u=10a`。每步奖励使用**原始毫米误差**，按提供的公式实现：

```text
r = -100 e_mm² - 0.1 u_V² - (u_V-u_prev_V)²
    + 2（当 |e_mm|<0.2）
```

位置/压力异常等明确失败终止的附加处理单独记录在环境代码中。不能把该奖励与换过误差单位的日志混用。

`Monitor` 记录原始奖励，优化器采用固定 `0.01` 倍奖励缩放以改善 critic 数值标度；日志与图表展示的仍是未缩放的平均每步奖励。SAC 的自动熵温度相对这个缩放后的奖励训练，这一选择明确保存在训练元数据中。

每条训练奖励日志先把每个已结束回合的总奖励除以其真实长度，再平均最近 30 个回合。初始随机动作可能产生很大的原始负奖励；当绝对值超过 10000 时，图 (a) 自动使用明确标注的对称对数纵轴，保留全部真实数值，不把它压成课件的线性 −180～0 范围。训练期带探索的奖励与确定性故障评估是不同统计量，不能相互替代。

每回合使用环境自己的随机数生成器做域随机化：质量 ±20%、初始油液体积模量 600–1400MPa、库伦摩擦 ±30%。训练若包含随机负载/刚度故障，则属于明确的故障数据增强；此时 5000N/50% 故障评估应称为包络覆盖下的仿真鲁棒性检验，不能写成未经训练覆盖的分布外泛化。未知随机参数仍可能造成部分可观测性，不宣称扩展观察量解决了所有隐藏状态。

## 熵、颤振与课件示意值

图 (a) 使用 tanh 后动作的真实对数概率计算微分熵，并换算为电压单位：`H(u)=H(a)+ln(10)`。连续分布的微分熵可以为负值，训练中出现负熵不等于计算错误。归一化动作最大微分熵只有 `ln(2)`；课件的初始约 2.8nat 不能解释为该归一化动作的熵。若把末期电压熵 0.35nat 显式设为目标，应说明它是参数选择，而不是人为强迫曲线“自发收敛”到该数值。

熵值是 actor 在真实 replay buffer 抽样状态上的蒙特卡洛估计；它不是动作时间序列直方图熵，也不是反向变换前高斯分布的熵。最初 `learning_starts` 步使用 SB3 随机探索动作，该阶段绘制的仍是尚未更新 actor 的条件分布熵，而非把随机预热的行为分布混标为 actor 输出。

图 (c)(d) 对 FP32 与 INT8 采用确定性均值动作。确定性评估不会保留随机策略的探索噪声，所以不额外加正弦波来仿造课件的“类颤振”。研究随机采样的死区概率穿越效应需要额外记录种子、随机动作和频谱。

课件的奖励 −2、熵 0.35、−14.1mm/s、0.08s、9.10V 等为参考示意值。本项目图注和报告只使用此次实际计算值；若趋势或数值未达到该参考，会在原始日志和指标中保留。

## HOCBF 的安全范围

提供的二阶公式适用于 `x_dot=v, v_dot=1850u−14v`（mm、mm/s）。图 (b) 明确验证这一约化模型：机械边界 0–100mm，预留 1.2mm 裕度。它与四状态压力对象是两个清楚区分的实验。

递归 HOCBF 取 κ1=κ2=24，因此 α1=48、α2=576。参考中的 580 对应判别式 `48²−4×580<0`，不能直接作为两个实正递归极点的乘积。滤波器检查初始高阶安全集和整个 1ms ZOH 区间的约束；可行时做最小距离投影，不可行则抛出错误。另用独立 DOP853 积分与随机状态做采样间数值复核。

本次约化模型的实际最低电压约 −0.30V，活塞渐近趋近 98.8mm；不写成固定 −3.1V。未保护轨迹到 100mm 的时刻通过求根得到，之后 CSV 为 NaN，表示实验结束，不构造碰撞后的平顶。图展示前 0.5s，报告给出完整 1s 终值。

四状态液压压力对象对电压的相对阶数更高；上述二阶证书不直接转移到该对象，也不构成真实设备在任意模型失配下的绝对安全保证。

## 剪枝、量化和实际计时

`edge_exporter.py` 提取真实 SAC actor 的确定性均值网络，按绝对值排序剪除约 70% 连接，避免百分位阈值在并列权重时误删全部或不删。固定掩码蒸馏如启用，会单独记录训练步数、损失和留出误差，不计作 SAC 环境交互步数。

校准与验证使用不重叠的 replay 记录行，但它们来自同一训练分布，并不是独立真机样本。另外，一次 FP32 commissioning 故障轨迹（当前 701 个采样记录，含预运行）明确参与激活范围校准，因此该故障轨迹不是完全留出实验。INT8 部署使用自身闭环观察重新计算动作，输出没有替换为 FP32 轨迹。

INT8 导出采用 SmoothQuant 式逐通道输入/权重平衡。令 `c` 为校准输入均值、`xmax_j=max|cal_j-c_j|`、`wmax_j=max|W_pruned[:,j]|`，`eps=1e-5`；alpha 依据最终校准集合选择，本次为 **0.5**：

```text
s_j = max(xmax_j,eps)^alpha / max(wmax_j,eps)^(1-alpha)
z = (o-c)/s
W' = W·diag(s), b' = b+Wc
```

中心化输入幅度小于等于 eps 的通道保留尺度 1，不删除该通道。首层折叠在量化前与原稀疏网络代数等价，保持剪枝掩码和 FP32/pruned 路径不变。alpha 在最终 12701 条校准记录上比较 INT8 对固定剪枝 FP32 actor 的动作 MAE：0.25 → 0.01717748，0.5 → 0.01679127，0.75 → 0.01752568，因此采用 0.5。候选结果保存在 [quantization_calibration_selection.json](outputs/quantization_calibration_selection.json)，留出观察及真实闭环输出不参与选参。这里的数据拟合尺度属于**边缘量化前缀**，与 Gym 环境固定工程尺度是两层不同处理；代码另保留 `balance_mode="mean_std"` 作为可复核选项，本次生产工件使用 SmoothQuant。

输入前缀用浮点计算，`c/s` 在导出时从校准集确定并保存，推理时不重新估计统计量。此后权重和层间激活为 INT8，点积和偏置累加为 INT32，定点重缩放为 INT64；输入量化和末端 tanh 也保留浮点。因此没有宣称全路径纯整数。权重量化范围包含零，零权重映射保持一致。`models/actor_int8.npz` 的 v2 格式持久化输入前缀，可独立加载而不依赖原始 FP32 权重；加载 v1 时保持原有恒等前缀。

存储对比使用实际输出文件大小；计时使用当前 CPU 的单样本重复实测，并分别报告中位数及 P95。本 NumPy 整数路径可能比 FP32 更慢，不能把课件的 0.06ms 或 92.5% 压缩率写成实测值。这里没有生成 MCU 固件或验证 DSP 硬实时性能。

这是非结构化连接剪枝；当前稠密 NumPy 数组不会跳过所有零连接，所以 70% 零权重不等于 70% 运算加速。Word 报告分别列出三种工件实际字节、三条推理路径的 CPU 中位数/P95、实际稀疏率、留出动作 MAE 和独立闭环速度 RMS 差。动作 MAE 使用归一化动作单位，乘以 10 才是电压 V。

没有真实液压试验台数据，本项目完成的是孪生训练与参数失配仿真验证，不包含真机小样本微调。第八章课后作业 8-4 的四种域随机化宽度研究不属于本次课堂实践范围。
